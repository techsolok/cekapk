## 3. What happened to the English Search control

**It was removed from the English header — nothing replaced it, and no search feature was built.**

The control was a blue "Search" pill linking to `/en`, which is the English homepage, not a search interface. There is no English search destination: the Meilisearch index is Indonesian-only, and the English app hub (`/en/aplikasi`) has no on-page search box (a Phase D item). Pointing it anywhere else would have been a second misleading link, and building an English search was explicitly out of scope for this phase.

What remains:
- **English header:** logo, Tools / Apps / Bahasa Indonesia nav, theme toggle. No Search pill on desktop or mobile (verified: zero `rounded-full` links in the EN header at 1440 and 390).
- **Indonesian header:** the "Cari" pill is unchanged (`/aplikasi`, the ID search target) — the working Indonesian search is untouched.
- English users who want to find an app now have the correct routes: header "Apps" → `/en/aplikasi`, footer "Apps in English" → `/en/aplikasi`, homepage CTA → `/en/aplikasi`, and the six guide links in the footer.

## 4. Bottom-navigation active-state results

Verified on the rendered local build (mobile 390px; `/en/tools` also at 360px). Active = `aria-current="page"` + `text-primary-dark`; exactly one item active per route, or none where no item applies.

| Route | Expected | Actual active | Result |
|---|---|---|---|
| `/en` | Home | Home | PASS |
| `/en/tools` | Tools | Tools | PASS |
| `/en/tools/tiktok-downloader` | Tools | Tools | PASS |
| `/en/aplikasi` | Apps | Apps | PASS |
| `/en/aplikasi/tiktok` | Apps | Apps | PASS |
| `/en/panduan/cara-instal-apk-aman` | none | none | PASS (Home no longer active — the bug is fixed) |
| `/` | Beranda | Beranda | PASS |
| `/tools` | Tools | Tools | PASS |
| `/tools/pengunduh-tiktok` | Tools | Tools | PASS |
| `/kategori` | Kategori | Kategori | PASS |
| `/kategori/game` | Kategori | Kategori | PASS |
| `/panduan/apakah-apkpure-aman` | none | none | PASS |
| `/keamanan` | Keamanan | Keamanan | PASS |
| `/en/tools` @360px | Tools | Tools | PASS |

"Indonesia" was inactive on every English route (its rule is exact `path === "/"`, which is never true on EN pages). Indonesian behaviour is unchanged: Beranda exact, Tools/Kategori/Keamanan active on their child routes.

**Implementation detail:** the old rule was `it.href === "/" ? path === "/" : path.startsWith(it.href)` — the `startsWith("/en")` made Home match everything. The new rule is `path === it.href || (it.href !== "/" && it.href !== "/en" && path.startsWith(it.href + "/"))`: Home (`/en`) matches only exactly; section items match themselves or a child path with a `/` boundary (so `/en/tools` never matches `/en/tools-x`, and `/tools` never matches a hypothetical `/tools-x`).
