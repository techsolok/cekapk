## 2. Part 1 — SEO corrections (all DONE)

### 1.1 Locale-aware WebSite JSON-LD
`websiteJsonLd(locale = "id")`. Indonesian output is byte-identical in meaning to before (`inLanguage: id-ID`, `https://cekapk.com`, SearchAction `https://cekapk.com/aplikasi?q={query}`). English output: `@id https://cekapk.com/en#site`, `url https://cekapk.com/en`, `inLanguage: en-US`, SearchAction `https://cekapk.com/en/aplikasi?q={query}`. `SiteChrome` renders the correct edition (it already received a `locale` prop from both layouts).

### 1.2 English application search hub — `/en/aplikasi`
Server component reading `searchParams.q`. Catalogue = the 11 English apps joined to their base records. The filter matches lowercase substring over `name + developer + taglineEn + English category name` (mirrors the Indonesian hub's behaviour, which also matches taglines — so `?q=tiktok` correctly returns TikTok **and** CapCut, whose English tagline mentions TikTok). States: no query (intro + link to the full Indonesian catalogue), results count + "Show all 11 apps", no-results box. Metadata/canonical/hreflang via `pageMetadata` (id-ID `/aplikasi`, en-US `/en/aplikasi`, x-default `/aplikasi`). All internal links use English URLs. The Indonesian hub is untouched apart from the reciprocal hreflang. The English SearchAction now points at this verified, working destination — no SearchAction points at a route that does not work.

### 1.3 English SoftwareApplication JSON-LD
`softwareAppJsonLd()` accepts `lang`, `description`, `pageUrl`. The English app template now emits SoftwareApplication (gated on `officialUrl`, as in Indonesian): `inLanguage: en-US`, `description` = the visible English tagline, `mainEntityOfPage` = the English page URL, `url` = the official Play Store URL, `offers` only when the record's price rule supports it (price "0", currency IDR). Indonesian keeps `id-ID` and the same gating. No invented ratings, review counts, or prices. No duplicate blocks: each app page emits exactly one WebSite block (via SiteChrome), one BreadcrumbList, one FAQPage (when FAQs exist), and at most one SoftwareApplication.
