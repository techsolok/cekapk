## What changed

### SEO-06 — Play Store links are now canonical (the top audit fix)
- All 49 Play Store links were search URLs
  (`play.google.com/store/search?q=…`). They are now canonical app pages
  (`play.google.com/store/apps/details?id=<packageId>`).
- Every package ID was verified against the live Play Store, one by one
  (`play-package-ids.md`, 50 rows). 48 fully verified by direct page load;
  Ruangguru (`com.ruangguru.livestudents`) and Google Meet
  (`com.google.android.apps.tachyon`) were re-opened and confirmed after an
  initial 429. Three wrong candidates were caught and corrected (Bstation is
  `com.bstar.intl`, not the global Bilibili app `tv.danmaku.bili`; Ruangguru is
  not `com.ruangguru`; Meet is not the old `com.google.android.apps.meetings`).
- Kucing APK stays `officialUrl: null` (info-only, not on Play) — correct.
- Developer fixes alongside the swap: Zoom `zoom.us` →
  `Zoom Communications, Inc.`; Alight Motion `Alight Creative, Inc.` →
  `SPLICE VIDEO EDITOR SRL` (acquired by Bending Spoons). Bstation stays
  `Bilibili (Bstation)` on purpose: Play's legal entity is BALABOOM PTE.
  LTD., but the brand users see is Bilibili — same brand-vs-legal call as
  Shopee/Tokopedia/Canva, which stay as brands. No package ID was invented;
  nothing unverified was swapped in.
- Wiring: `packageId` added to `ExpansionRecord`; `buildExpansionApp` builds
  the details URL from it; the 10 pillar apps store the canonical URL
  directly. `npm run check:seo` now fails the build if any Play search URL
  ever returns to `src/`.

### SEO-06 — expansion template duplication fixed
- The 39 expansion pages shared 7–8 of 14 core paragraphs word-for-word.
  All 7 shared paragraphs now have 9 group-specific variants (one per
  permission profile: game, social, creator, streaming, shopping, finance,
  productivity, education, utility) — 63 variants + 9 permission-list intros
  (`expansion-template-variants.md`, applied by
  `scripts/apply-phase2-variants.py`).
- Wiring: profile-keyed records in `expansion-shared.ts` (`WORKFLOW_P2`,
  `SAFETY_P1`, `FAQ_SAFE`, `FAQ_FREE_TAIL`, `FAQ_INSTALL`,
  `FAQ_UNAVAILABLE`, `FAQ_ACCOUNT`, `PERMISSIONS_INTRO`) with a `fill()`
  helper for `{name}` / `{developer}` / `{priceLabel}`. The gratis FAQ keeps
  its per-app price label as the first sentence; only the tail varies, so no
  price fact changed. `PROFILE_SAFETY` already had 9 distinct texts — no
  change there. `check:seo` now asserts all 9 variants are pairwise distinct
  in each of the 8 records.
- Honest limits kept: where the steps genuinely are the same (install FAQ
  first sentence, unavailable FAQ closing advice), the wording stays shared
  on purpose — noted in the variants file.

### SEO-09 — full-site link crawler (DONE, site is clean)
- New script `scripts/check-links.mjs` + `npm run check:links`: auto-starts
  the local build, crawls all 7 sitemap segments, checks every internal
  link, reports broken links, 404s, orphans, missing alt, missing canonical.
- First full run (`link-audit-2026-11-06.md`): 104 sitemap URLs, 139 distinct
  internal URLs checked, **0 broken, 0 orphans, 0 pages without canonical,
  0 images missing alt**. Re-run any time with `npm run check:links`; it
  exits 1 on any breakage, so it can gate a deploy.

### SEO-13 — deeper contextual linking (DONE)
- App pages now show a "Panduan Terkait" section, derived from the guides'
  own `relatedApps` data — no invented links. 7 apps get guide links
  (WhatsApp 6 guides, TikTok 2, Bstation 2, Telegram 2, Minecraft 2,
  CapCut 1, Kucing APK 1). Guide pages already linked to apps; now the link
  runs both ways.
- Instagram's app page now links the Instagram downloader tool
  (`relatedTool`, mirroring the TikTok pattern that already existed).

### SEO-14 — per-page OG images (DONE)
- 5 dynamic `opengraph-image.tsx` routes (`next/og`): ID app, ID guide, ID
  category, EN app, EN guide. Each renders a branded 1200×630 card (blue
  gradient, CekAPK wordmark, page title, real subtitle from the page data).
  No app logos, no screenshots, no invented ratings/badges. Verified live
  locally: all 5 routes return HTTP 200 `image/png` 1200×630, and the card
  was visually checked.
- `pageMetadata` gained an `ogImage: "dynamic"` option: when set, it leaves
  `images` out of the metadata entirely so Next's file convention supplies
  the image (its URL carries the build hash suffix, e.g.
  `/opengraph-image-lexgr5`). Pages without a dynamic image keep
  `/og-default.jpg`. One real bug found and fixed while verifying: satori
  requires `display: flex` on any div with more than one child — the first
  render 404'd with that error until the card's middle wrapper got it.

### SEO-15 — structured data validation (DONE, 0 errors)
- Ran the live pages through validator.schema.org on 6 Nov 2026 evening
  (after a Google "unusual traffic" check on the validator itself, cleared
  once): homepage **0 errors, 0 warnings** (WebSite + FAQPage); TikTok app
  page **0 errors, 0 warnings** (SoftwareApplication + BreadcrumbList +
  WebSite + FAQPage); /keamanan **0 errors, 0 warnings** (WebSite only —
  that page carries no Organization/FAQ/Application markup by design).
- This run tested the Phase 1 deployment. Phase 2 only changes the
  SoftwareApplication `url` to the canonical Play URL (same structure), so a
  quick re-run of the TikTok page after the Phase 2 deploy is enough to
  confirm nothing regressed — no new schema work needed.
